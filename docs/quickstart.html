1. pyinfercnv 是什么

pyinfercnv 是 R 包 inferCNV（Broad Institute）的纯 Python 重写， 原生面向 AnnData 数据结构，通过 Numba JIT 加速热点 kernel（Viterbi、tail smoothing 等）。 目标是在 scRNA-seq 数据上做单细胞层面的 CNV 推断，与 R 版本保持算法 parity 的同时提供显著的 runtime 加速。

当前版本 0.2.0.dev2。README 原话： "pyinfercnv is a Python-accelerated re-implementation of R infercnv"。 Phase 2（tumor subclustering + HMM i3/i6 + hspike calibration + CNV region calls）已完成并通过 R-parity 验证； Phase 3（BayesNet MCMC + denoise）尚未实现。 交付物为 py3-none-any wheel（纯 Python，无 .so/.pyd/.dylib），首次调用时 Numba 编译。

ℹ 初次观测的 py-vs-R wallclock 加速：25–192×（0.5–1.4 kilocell 输入，见 scripts/phase2_benchmark/）。 这是 wallclock + 回归检测 harness，不是外部真实世界的 correctness 验证。

2. 安装

pyinfercnv 支持的 Python 版本：≥ 3.10，< 3.13。

bash 
# 核心安装
pip install pyinfercnv

# 可选 extras
pip install 'pyinfercnv[viz]'        # + matplotlib，热图可视化
pip install 'pyinfercnv[compare]'    # + hmmlearn，Phase 2+ parity 交叉验证
pip install 'pyinfercnv[dev]'        # + 测试和构建工具链

extras 说明

  • [viz]：引入 matplotlib，用于 pyinfercnv.viz.plot_cnv_heatmap 绘制 log2(FC) 热图（无 omicverse 依赖，配色硬编码对齐 ov 面板）。
  • [compare]：引入 hmmlearn，Phase 2 及后续阶段做 HMM parity 交叉比对时使用。
  • [dev]：test + build 工具链（pytest 套件、python -m build 轮子构建等）。

内置基因坐标

wheel 自带三套 gene-position parquet：

  • hg38 — GENCODE v45 basic
  • hg19 — GENCODE v19
  • mm10 — GENCODE vM25

通过 pyinfercnv.io.genome.load_gene_positions(genome="hg38") 读取，无需联网下载。

3. 最小可运行示例

3.1 Python API

默认 count layer 名为 "counts"。下面是 README 给出的标准用法，完成 gene_pos 合并 + 调用 infercnv()：

python 
import scanpy as sc
from pyinfercnv import infercnv
from pyinfercnv.io.genome import load_gene_positions

adata = sc.read_h5ad("my_dataset.h5ad")

# 把基因坐标 merge 进 adata.var（假设 index 是 gene_symbol）
gene_pos = load_gene_positions(genome="hg38")
adata.var = adata.var.merge(gene_pos.set_index("gene_symbol"),
                            left_index=True, right_index=True, how="left")

infercnv(
    adata,
    reference_key="cell_type",
    reference_cat=["Microglia", "Oligodendrocytes"],
    key_added="cnv",
)

# 运行结束后可用字段：
#   adata.obsm["X_cnv"]                — log2(FC) CNV 矩阵
#   adata.uns["cnv"]["chr_pos"]        — 染色体 → bin 起始索引
#   adata.uns["cnv"]["profile"]        — 每个 block 的 wallclock / RSS
#   adata.uns["cnv_ref_counts_raw"]    — 参考组原始 counts（Phase 2 准备）

如需启用 Phase 2（HMM + subcluster），显式传入 InferCNVConfig：

python 
from pyinfercnv import InferCNVConfig, infercnv

cfg = InferCNVConfig(
    cutoff=1.0,                  # smart-seq2 取 1.0；10x UMI 数据改为 0.1
    HMM=True,
    HMM_type="i6",               # 或 "i3"
    BayesMaxPNormal=0.0,          # Phase 3 filter 关闭，保持 R-parity
    cluster_by_groups=True,
    tumor_subcluster_partition_method="leiden",
    prune_outliers=True,
)
cfg.validate()

result = infercnv(
    adata,
    config=cfg,
    reference_key="annotation",
    reference_cat=["Microglia/Macrophage", "Oligodendrocytes (non-malignant)"],
    inplace=False,
)
print(result.cnv_matrix.shape)           # (n_cells, n_bins)
print(result.hmm_states.shape)           # (n_cells, n_bins), int8, 0-5

⚠ 数据类型对应的 cutoff： smart-seq2 用 cutoff=1.0（R wiki 默认），10x Genomics UMI 数据必须改为 cutoff=0.1。 这是 R infercnv 官方 wiki 明确列出的数据类型相关参数，唯一一个。

4. 输出字段详细说明

infercnv() 运行成功后会把结果写回 AnnData 对象（inplace=True） 或返回一个 InferCNVResult 实例（inplace=False）。 下表列出关键输出（key_added 默认为 "cnv"）：

4.1 AnnData 持久化字段

字段形状 / dtype说明
adata.obsm["X_cnv"] (n_cells, n_bins)
float32		 Phase 1 的 log2-FC CNV 矩阵。每个 bin 是经过平滑、中心化、outlier prune 后的 log2 倍差信号： > 0 表示扩增（amplification），< 0 表示缺失（deletion）， 量级大致落在 [-1, 1]（观察值，典型绘图 vmin=-0.3, vmax=0.3）。
adata.uns["cnv"]["chr_pos"] dict[str, int] 有序映射：染色体名 → 在 X_cnv 列方向上的起始 bin 索引。画热图时用来切染色体条带。
adata.uns["cnv"]["profile"] dict 每个执行 block 的 wallclock_s（秒）和 rss_delta_mb（psutil 记录的内存增量）。用于性能剖析。
adata.uns["cnv_ref_counts_raw"] (n_ref_cells, n_genes)
float32 dense		 参考组在 CPM 归一化之前的原始 counts，Phase 2 calibrate_i6_emission 需要。
adata.obs["cnv_subcluster"] (n_cells,)
int32		 Phase 2 Leiden tumor subcluster 标签（cluster_by_groups=True 时按注释分组独立聚类）。
adata.obsm["X_cnv_hmm_states"] (n_cells, n_bins)
int8		 i6 HMM state 矩阵（见下）。
adata.obsm["X_cnv_hmm_states_i3"] (n_cells, n_bins)
int8		 i3 HMM state 矩阵（见下）。

4.2 InferCNVResult 主要字段

字段说明
cnv_matrix log2-FC 矩阵（float32）。等价于 adata.obsm["X_cnv"]。
cnv_matrix_fc 线性 FC 空间 = 2 ** cnv_matrix，中心在 1.0 附近。
hmm_states i6 HMM state，取值 0–5（py 0-indexed）。语义： 0, 1 = deletion；2, 3 = neutral；4, 5 = amplification。 与 R 的 1-indexed（1–6，neutral=3）相差 1，跨语言比对需要先减 1。
hmm_states_i3 i3 HMM state，取值 0 / 1 / 2（py 0-indexed）： 0 = del，1 = neutral，2 = amp。
cnv_regions BED 风格 DataFrame，列：[cell_group, chromosome, start, end, state]。 对 HMM state 做 RLE 合并后得到的 per cell-group × chromosome 区段表。 启用 Phase 3 (BayesMaxPNormal > 0) 后会多一列 posterior_p_normal。
subclusters 每细胞的整数 subcluster 标签（int32）。
profile 每 block 的 wallclock + RSS（同上）。

⚠ HMM state 编码差异： pyinfercnv 的 HMM state 是 0-indexed（i6: 0–5，neutral=2；i3: 0–2，neutral=1）。 R infercnv 的 @expr.data 是 1-indexed（i6: 1–6，neutral=3；i3: 1–3，neutral=2）。 做 elementwise 比对前先把 R 侧减 1。

5. Phase 进度一览

Phase范围状态说明
Phase 1 预处理 / 平滑 / 中心化 / outlier prune / invert log2 大部分 bit-exact 在 oligodendroglioma step-TSV fixture 上，除 step10 smooth 仍为 max_diff ~1e-3（scipy uniform_filter1d 累加顺序差异，尚未收紧）外， 其余 Phase 1 步骤（step03 normalize / step04 log2 / step08 subtract_ref / step09 max_threshold / step11 center / step14 invert_log2 / step16 prune_outliers） 均已升级到 max_diff < 1e-10（bit-exact）。 step02 filter_genes 是基因集相等（set-equality），非数值比对。
Phase 2 Leiden tumor subcluster + HMM i3/i6 + hspike calibration + CNV regions 完成 oligo 上：subcluster ARI 1.000；HMM i3 端到端 Jaccard 1.000；HMM i6 端到端 Jaccard 0.979（R-parity 测试 floor 0.99 / 0.96）。 Viterbi kernel 在 R 对齐输入下 Jaccard 0.9999。
Phase 3 BayesNet MCMC / mask_non_DE / noise_reduction / 变分近似 TODO，未实现 R 的 inferCNV_BayesNet (Gibbs)、inferCNV_mask_non_DE、noise_reduction 以及 Phase 3b 的变分近似均尚未有 Python 实现。 相关字段（posterior_p_normal、denoise=True 配置等）保留 schema 占位。

⚠ Phase 1 → Phase 2 有精度截断： Phase 1 内部用 float64 算出 bit-exact 中间量，但在 result.cnv_matrix 处被强制 cast 回 float32（公开契约）。 因此"Phase 1 bit-exact" 的精度收益目前不会传递到 HMM state 调用。把 Phase 2 改为直接消费 float64 中间量是后续工作 （见 docs/superpowers/HANDOFF_bit_exact.md §8）。

6. Parity 指标（Phase 2）

6.1 主指标 — 连续 CNV 矩阵 Spearman ρ

step-14 post-Phase-1 cnv_matrix 是下游所有步骤（HMM、region calls、热图）消费的连续 log2-FC 信号， 其 py-vs-R 的秩相关系数是最关键的 parity 声明。

Fixture cells genes per-cell ρ (mean ± std) global flat ρ Pearson
oligodendroglioma (smart-seq2，R 自带 fixture) 184 8508 0.9998 ± 0.0001 0.9998 0.9928
Gao2021_Breast / DCIS1 (10x UMI，3CA) 1399 9237 1.0000 ± 0.0000 1.0000 0.9980
Gao2021_Breast / TNBC1 (10x UMI，3CA) 1022 9654 1.0000 ± 0.0000 1.0000 0.9964
Gao2021_Breast / TNBC3 (10x UMI，3CA) 520 10835 1.0000 ± 0.0000 1.0000 0.9987

6.2 次指标 — HMM state Spearman ρ（离散化后）

HMM state 是对连续 CNV 矩阵的分桶视图（i3: 0/1/2；i6: 0–5），秩相关衡量 py 与 R 是否把同一个 bin 放进同一个幅值桶：

DCIS1i30.9202 ± 0.0560.9208
DCIS1i60.8273 ± 0.0520.8178
TNBC1i30.9610 ± 0.0230.9615
TNBC1i60.7524 ± 0.0470.7415
TNBC3i30.9323 ± 0.1450.9578
TNBC3i6— (R hspike 在该 fixture 上 crash，不可比)

从连续矩阵的 ρ ≈ 1.0 掉到 HMM state 的 ρ 0.75–0.96 是离散化放大： 当连续 log2-FC 值接近 state 边界时，py 与 R 之间的浮点微差可能把个别 bin 翻到相邻桶， 但底层信号的一致性并未改变。

7. ⚠ Consistency ≠ Correctness（必读）

⚠ Parity 只是对 R infercnv 自身的复刻，不是对外部 ground truth 的验证。

  1. 本项目测量的是 py-vs-R 的一致性，不是对 WGS、copykat、numbat、inferCNA 等外部 CNV caller 或金标准的 correctness 验证。 要做真正的 correctness 验证，需要匹配的 WGS 数据或独立 CNV caller 作为对照。
  2. Parity 声明的适用范围有限：目前仅在 R infercnv 自带的 smart-seq2 oligodendroglioma fixture 以及 3CA 的三位 10x UMI 乳腺癌患者（Gao2021_Breast: DCIS1 / TNBC1 / TNBC3）上测量。 在其他数据集上 py 与 R 的一致性需要重新测量。
  3. 3CA 的 cell-type 注释是上游自动标签，不是专家金标准。 py 和 R 在基准 harness 中共享同一份 ref_group_names，因此注释本身的任何瑕疵对两侧都是共享的， 不能用这个 harness 去裁决哪一侧"正确"。
  4. 不要跨 assay 类型外推 parity 结论。 smart-seq2 和 10x UMI 的预处理参数不同（cutoff=1.0 vs 0.1）， 一个 assay 上达到的 parity 不能直接推广到另一个 assay。
  5. Subcluster ARI 已不再作为主 parity 指标（2026-04-23 起）。 Leiden 输出的整数 cluster ID 是算法内部的任意标签，跨语言无语义契约； ARI 只衡量标签置换一致性，不反映 py 和 R 是否产出相同的科学信号。 主指标改为连续 CNV 矩阵的 Spearman ρ（见 §6.1）。
